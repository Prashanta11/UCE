1. Executive Summary
UCE is intended to become an AI-native creative operating system rather than a conventional video editor. Its
core technical thesis is that recorded or generated media should be represented as a persistent, editable world
containing entities, geometry, motion, events, audio, relationships, dependencies, uncertainty, and provenance.
Users should be able to select semantic entities, express desired changes in natural language or through
deterministic controls, and have UCE plan and execute operations while preserving all locked state.
The architecture therefore combines a semantic World Graph, Universal Entity Identity (UEI), OpenUSD-based
scene state, OpenTimelineIO editorial state, deterministic and generative execution paths, content-addressable
storage, GPU-native media surfaces, model routing, specialist agents, policy enforcement, quality critics,
localized self-repair, provenance, and continuous security/privacy/testing gates.
The first production milestone is deliberately narrow: import a real video, create a project, select and
persistently track a semantic entity, remove that entity using reconstruction-first processing, verify the result,
repair localized defects, and export the result without violating local-first privacy or non-destructive project
requirements.
2. Purpose and Scope
2.1 Purpose
This SRS provides the requirements baseline for product planning, architecture, engineering, ML research,
security, QA, infrastructure, and design. It is intended to be sufficiently precise for team decomposition and
implementation planning.
2.2 In Scope
 AI-native video and media transformation.
 Semantic entity selection and tracking.
 Object removal, replacement, insertion, and dependency-aware editing.
 Persistent World Graph and Universal Entity Identity.
 Non-destructive operation graph and semantic undo/branching.
 Hybrid deterministic, procedural, simulation, and generative execution.
 3D/4D reconstruction interfaces and OpenUSD integration.
 Audio understanding and cross-modal dependency linking.
 Local-first execution with optional cloud compute.
 Security, privacy, provenance, auditability, plugin sandboxing, and continuous testing.
 Open plugin/model capability protocol and industry-standard interoperability.
2.3 Out of Scope for V0
 Training a frontier-scale proprietary text-to-video foundation model.
 Reimplementing mature codecs, color science, scene formats, or physics engines from scratch.
 Full Blender/Houdini/Nuke feature parity.
 Long-form autonomous filmmaking.
 General-purpose copyright-detection evasion or platform fingerprint bypass.
 Mass-market collaboration or enterprise administration before core local editing is stable.

14. World Graph and Dependency Model
 World Graph SHALL model entities, events, relations, temporal state, locks, dependencies, uncertainty, and
provenance.
 Dependencies MAY cross modalities, for example vehicle motion -> engine audio or visual entity -> cast
shadow.
 Changing authoritative state SHALL invalidate affected dependent computations.
 Dependencies SHOULD distinguish causal/required dependencies from weak inferred associations.
 Observed, estimated, and generated state SHOULD carry confidence/provenance labels.

16. Model Runtime and Router
 Models SHALL be exposed as capabilities rather than hard-coded product dependencies.
 UCE SHOULD support PyTorch during research and portable/optimized runtimes such as ONNX/TensorRT
where appropriate.
 Safetensors SHOULD be preferred for raw tensor weight storage where supported.
 Each model SHALL have a capability manifest containing identity, version, capabilities, runtime, weight
format, hardware requirements, license, permissions, and benchmark metadata.
 The router SHOULD consider quality, latency, privacy, hardware, license, cost, resolution, and availability
when selecting a backend.
 Local/private policy SHALL override quality-based routing when external execution is not permitted.

1. V0 Engineering Goals
 Prove that UCE project semantics remain independent from any one AI model.
 Prove Universal Entity Identity can survive segmentation/tracking operations without being owned by a
tracker.
 Prove non-destructive operations, CAS-backed artifacts, transactional saves, and rollback/recovery.
 Prove local-only privacy: the complete V0 workflow must succeed with networking blocked.
 Prove worker isolation: an AI worker failure must not corrupt project state or terminate the desktop shell.
 Prove measurable edit quality through preservation, temporal consistency, and defect-localization checks.

5. Authoritative Project Model
V0 SHALL not store authoritative state inside generated media files, model checkpoints, or worker-local caches.
The desktop project controller is the only authority allowed to commit a new project revision.

6. Content-Addressable Storage (CAS)
ID Priority Design requirement
CAS-001 MUST Every immutable source or
derived binary artifact has a
cryptographic content hash.
CAS-002 MUST Project revisions reference
artifacts by logical AssetRef, never
by ad-hoc absolute paths.
CAS-003 MUST CAS writes are atomic: write temp
-> hash/verify -> fsync where
applicable -> publish.
CAS-004 MUST Garbage collection removes only
blobs unreachable from retained
revisions/pins.
CAS-005 SHOULD Operation cache keys include
operation type/version, input
hashes, normalized parameters,
model hash, and deterministic
settings.
CAS-006 MUST Cache eviction must never delete a
source artifact or an artifact
reachable from a committed
project revision.
AssetRef {
algo: 'sha256' | 'blake3'
digest: string
media_type: string
byte_size: uint64
logical_role: source | proxy | mask | depth | render | metadata | model_output
}

7. Transactional Project Saving and Recovery
1. Build new immutable artifacts in CAS.
2. Validate hashes and schema versions.
3. Create candidate ProjectRevision.
4. Write revision record atomically.
5. Update project HEAD pointer atomically.
6. Only after HEAD commit may old unreferenced cache become GC-eligible.
 Unexpected termination before step 5 leaves the previous revision authoritative.
 Worker outputs not referenced by a committed revision are temporary/orphan artifacts and may be
reclaimed.
 Recovery on startup validates HEAD and falls back to the previous valid revision if corruption is detected.

12. Reconstruction-First Object Removal Pipeline
Select entity
-> propagate temporal mask
-> mask cleanup / dilation policy
-> identify recoverable pixels from adjacent frames / motion
-> propagate/reconstruct visible background evidence
-> generate/inpaint only unresolved regions
-> composite temporally
-> quality evaluation
-> localized repair if needed
-> commit result as operation output
V0 shall not claim physically complete interaction deletion. Interaction-aware restoration (deformations,
reflections, linked audio, etc.) is a later dependency-graph milestone, but V0 interfaces must not preclude it.

16. Security Boundaries
 Main UI process: trusted, no arbitrary model/plugin execution.
 Workers: isolated process identity, project-scoped capabilities, constrained filesystem roots.
 Model artifacts: hash verified; unsafe Python/pickle loading prohibited in production mode unless explicitly
sandboxed.
 IPC messages: schema-validated, size-limited, versioned, and reject unknown privileged fields.
 Archive/project import: path traversal and symlink escape protection mandatory.

21. V0 User Workflow
1. New Project
2. Import video
3. UCE hashes source and creates CAS entry
4. Probe + proxy generation
5. User seeks to frame and clicks/boxes target
6. Vision worker returns initial mask
7. Project creates UEI entity
8. User confirms target and frame range
9. Vision worker propagates temporal mask
10. Remove operation creates candidate
11. Quality worker evaluates preservation + temporal consistency
12. Repair operation runs if needed/available
13. User compares before/after
14. Commit operation result to project revision
15. Export final media
